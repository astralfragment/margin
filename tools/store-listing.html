Margin {{version}} for the Chrome Web Store

Everything the store asks for, ready to paste. Upload {{storeZip}} from this folder. It has no pinned key, because the store refuses manifests that carry one and assigns its own ID.

First submission

  1. Sign in to the Chrome Web Store developer dashboard with the account that should own Margin, and pay the one-time registration fee.
  2. Click New item and upload {{storeZip}}.
  3. Fill in Store listing, Privacy and Distribution with the text below.
  4. Add at least one screenshot, 1280 by 800 or 640 by 400. The report with numbered annotations or the welcome page make good first shots.
  5. Submit for review. Reviews usually take a few days.

Shipping an update

  1. Raise version in extension/manifest.json. The store rejects a version it has seen.
  2. Run npm run package in the project folder.
  3. In the dashboard, open Package, upload the new web store zip and submit.
  4. After review, Chrome updates everyone within a few hours. The folder zip from the same run goes to anyone still on a folder install.

Description

Margin is a free website annotation and visual feedback tool for Chrome. Annotate any web page, mark up screenshots with numbered notes, and turn UI issues into clear bug reports for Jira, Figma, Google Docs, Word or PDF. No account and no sign-up.

Annotate websites in seconds

Drag over anything on a web page that looks wrong. Margin takes a screenshot of that area and opens a comment card beside it. Give the comment a title and a severity, add a note, and pin numbered markers on the exact details. Boxes and arrows point out spacing, alignment, copy and layout problems.

Report bugs where your team already works

- Create Jira issues with the screenshots attached and priority set from severity, one per comment or one for the whole review
- Post feedback as comments on the matching Figma frame for design review
- Copy the review into Google Docs with images and numbered lists intact
- Export to Word, PDF, HTML, or Markdown for GitHub issues, Slack and AI coding agents

Built for website QA and design QA

- Capture mobile, tablet and desktop widths in one click for responsive testing
- Screenshot a selected area, a single element or the whole visible screen
- Track each issue as Open, Fixed or Won't fix, and filter by severity and status
- Verify fixes in one pass with before and after screenshots side by side
- Record the browser, operating system and zoom on every comment so bugs are easy to reproduce
- Share a whole review as one file that a teammate can open in their own Margin

Who uses Margin

UI and UX designers checking a build against the design. Front-end and web developers logging layout bugs. QA testers running website QA. Product managers doing UAT and acceptance testing. Agencies and freelancers collecting client feedback on websites and web apps.

What's new in 0.5

- A new comment card that opens beside the area you mark and never covers it. Type a title, press Enter, done.
- Reviews linked to a Jira ticket and a Figma file, with the ticket's details and the file's frames brought in.
- Light theme by default, with Dark and Match system in settings.
- Much faster saving, with no more pages pausing on large reviews.
- Picks the right element under the pointer, stays on top of page dialogs, and keeps its size on zoomed pages.
- Hold Alt to use the page while you annotate, and comment from the keyboard.
- A clearer report, with filters that match, one comment number everywhere and safer editing.

Free and private

Margin is free, with no account and no tracking. Screenshots and comments stay in your browser until you choose to send them to Jira or Figma.

Privacy tab

Single purpose
Capture and annotate screenshots of issues on web pages, and export them as a review document.
activeTab
Takes the screenshot and shows the annotation layer only on the tab where the user starts annotating.
scripting
Adds the annotation layer to that tab when the user starts annotating.
storage
Keeps comments, screenshots and settings on the user's computer.
unlimitedStorage
Screenshots outgrow the default local storage limit after a few reviews.
clipboardWrite
Copy for Docs puts the finished review on the clipboard.
contextMenus
Adds start annotating, comment on the whole visible area, and open the report to the right-click menu.
identity
Opens the Jira or Figma sign-in window when the user connects one of them in Help and settings or in the report.
Host permissions
None at install. api.atlassian.com and api.figma.com are optional and requested only when the user connects Jira or Figma, to create issues, attach screenshots and post comments. *.atlassian.net is optional and requested only when the user presses Find my site, to find their open Jira site and list its projects through their existing Jira sign-in.
Remote code
No. All code ships inside the package.
Data usage
Tick Authentication information and Website content. Leave every other type unticked. Authentication information covers the Jira and Figma sign-in tokens, which pass through the Margin sign-in helper on lilacfragment.co.za once at sign-in and at each renewal, and are not stored there. Website content covers the screenshots, page addresses and notes the user chooses to send to Jira or Figma. Certify all three statements, since nothing is sold, used for anything but sending the review, or used for lending.

Distribution

Choose Private and limit it to your Google Workspace domain if the team signs in to Chrome with Workspace accounts. Otherwise choose Public, so Margin shows up in store search. Unlisted hides it from search.

The store copy gets its own ID, separate from the folder install {{id}}. People moving over should download their reviews as Word or HTML first, then remove the folder copy.
