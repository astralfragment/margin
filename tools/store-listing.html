Margin {{version}} for the Chrome Web Store

Everything the store asks for, ready to paste. Upload {{storeZip}} from this folder. It has no pinned key, because the store refuses manifests that carry one and assigns its own ID.

First submission

  1. Sign in to the Chrome Web Store developer dashboard with the account that should own Margin, and pay the one-time registration fee.
  2. Click New item and upload {{storeZip}}.
  3. Fill in Store listing, Privacy and Distribution with the text below.
  4. Add at least one screenshot, 1280 by 800 or 640 by 400. The report with numbered annotations or the welcome page make good first shots.
  5. Submit for review. Reviews usually take a few days.

Shipping an update

  1. Raise version in extension/manifest.json. The store rejects a version it has seen.
  2. Run npm run package in the project folder.
  3. In the dashboard, open Package, upload the new web store zip and submit.
  4. After review, Chrome updates everyone within a few hours. The folder zip from the same run goes to anyone still on a folder install.

Store listing

Name
Margin
Summary
Mark up UI issues on any page, number the details, and export a clean review for Docs or Word.
Category
Developer Tools
Language
English
Description

Margin lays a sheet over the page you are reviewing. Drag over anything that looks wrong and Margin takes a screenshot of it. Write what is wrong, pick a severity, and move on to the next one.

In the report, open any screenshot to add numbered markers, boxes and arrows, each with its own note. Move or resize the marked region, zoom in, and right-click a number to remove it.

When the round is done, copy the whole review into Google Docs or download it as a Word or HTML file. Numbered notes come out as a numbered list. Recheck a comment after the fix to show it before and after.

Send the review to Jira or Figma when it is ready. Connect once and Margin creates Jira issues with the screenshots attached, or posts each comment on the Figma frame it links to. Without signing in, Margin opens Jira's own create form with the text filled in.

Everything stays on your computer until you send it. Margin has no account and no tracking.

Privacy tab

Single purpose
Capture and annotate screenshots of issues on web pages, and export them as a review document.
activeTab
Takes the screenshot and shows the annotation layer only on the tab where the user starts annotating.
scripting
Adds the annotation layer to that tab when the user starts annotating.
storage
Keeps comments, screenshots and settings on the user's computer.
unlimitedStorage
Screenshots outgrow the default local storage limit after a few reviews.
clipboardWrite
Copy for Docs puts the finished review on the clipboard.
contextMenus
Adds start annotating, comment on the whole visible area, and open the report to the right-click menu.
identity
Opens the Jira or Figma sign-in window when the user connects one of them in Help and settings or in the report.
Host permissions
None at install. api.atlassian.com and api.figma.com are optional and requested only when the user connects Jira or Figma, to create issues, attach screenshots and post comments. *.atlassian.net is optional and requested only when the user presses Find my site, to find their open Jira site and list its projects through their existing Jira sign-in.
Remote code
No. All code ships inside the package.
Data usage
Tick Authentication information and Website content. Leave every other type unticked. Authentication information covers the Jira and Figma sign-in tokens, which pass through the Margin sign-in helper on lilacfragment.co.za once at sign-in and at each renewal, and are not stored there. Website content covers the screenshots, page addresses and notes the user chooses to send to Jira or Figma. Certify all three statements, since nothing is sold, used for anything but sending the review, or used for lending.

Distribution

Choose Private and limit it to your Google Workspace domain if the team signs in to Chrome with Workspace accounts. Otherwise choose Unlisted, which hides it from search and works for anyone with the link.

The store copy gets its own ID, separate from the folder install {{id}}. People moving over should download their reviews as Word or HTML first, then remove the folder copy.
